# 再生塑料配方试配筛选（质检模型 + 最优改配求解 + 局部风险核查）

面向再生塑料配方研究员的网页工具：

1. **试配筛选**（`/`）：录入原配方与各原料的上下限、锁定项后，在**合格概率 ≥ 0.7**
   的约束下，按 **先最少改变原料种数、再最小化总克数改变量** 的字典序求出最优试配方案；
   只有求解器**证明**无解才报无解，求解失败单独报告。
2. **局部风险核查**（`/audit`）：粘贴独立抽检的四料配方与实测合格标签，找出模型在哪些
   叶节点（对应一段用料区间）误放行偏多，并对全部叶做 **95% 同时置信核查**，为“是否
   暂停该区间自动放行”提供依据。

## 技术栈与模型

- **FastAPI** 提供网页与 JSON API；**scikit-learn** 训练随机森林；**z3-solver** 求解；
  **scipy.stats.beta** 计算 Clopper–Pearson 置信下界。
- 质检模型：`RandomForestClassifier(n_estimators=5, max_depth=3, random_state=20241117)`，
  在固定种子生成的合成数据上训练（Dirichlet 采样的配方比例 + 含噪质检规则，阈值取中位数
  使类别均衡）。每次启动以同一种子重训，结果确定（自测第 1 项验证同种子重训一致）。
- 配方为 4 种原料的整数克数，总重 1000 克；模型输入为克数 ÷ 1000 的 **float32** 比例。

## 求解语义（与分类器严格一致）

- sklearn 树内部以 float32 特征与 float64 阈值比较。求解器把每个分裂条件
  `float32(g/1000) <= τ` 预计算为等价的**整数截断** `g <= K`（`app/model.py: cutoff_left`），
  因此 z3 中的约束与原分类器的实际阈值语义逐点一致（自测第 2 项对全部阈值 × 0–1000 克逐点核对）。
- 森林概率 = 5 片叶子概率（精确有理数）之和 / 5 ≥ 0.7，以精确有理数编码进 z3。
- 字典序优化用**两阶段**实现：先最小化改动种数，固定该最优值后再最小化总改动克数。
- 每份建议解出后**用原 sklearn 分类器复算概率**（float32 输入），未通过复核则按求解失败上报，
  绝不当作合格建议展示。
- 结果状态严格区分：`ok`（已证明最优）/ `infeasible`（z3 判定 unsat，即证明无解）/
  `invalid`（输入不合法）/ `solver_failure`（z3 unknown、超时或异常，**不**当作无解）。

## 页面与交互

顶部导航可在「试配筛选」与「局部风险核查」间切换，两个入口共用同一个启动时训练好的模型。

### 试配筛选（`/`）

- 录入：4 种原料的原配方克数、各自下限/上限、锁定勾选；总重须为 1000 克。
- 「载入可行样例」「载入无解样例」：样例在服务启动时由真实模型 + 求解器**实测验证**后生成
  （`app/samples.py`），可行样例含锁定项，无解样例为上下限把配方逼入不合格区域的情形。
- **计算期间可随时修改**：任何输入修改会立即撤下旧建议（清空结果区）、中止在途请求；
  迟到的旧响应按请求序号（epoch）比对后直接丢弃，不会恢复显示（`app/static/index.html`）。
- 结果展示：合格概率（原分类器复算值）、逐原料改动明细、改动种数、总克数、最优性结论、求解耗时。

### 局部风险核查（`/audit`）

- 录入：30～300 行抽检记录，每行「4 个整数克数 + 实测标签」，克数合计须为 1000 克；
  标签可用 `合格/不合格`、`1/0`、`是/否`、`true/false` 等，分隔符可为空格、逗号或制表符。
  另有风险上限（0～1，默认 0.05）。「载入示例抽检数据」提供固定种子的 120 行演示数据。
- **放行口径与原分类器完全一致**：克数 ÷ 1000 的 **float32** 比例送入同一分类器，
  概率 ≥ 0.7（含 1e-9 容差，与求解器复核口径相同）即记为「模型放行」。
- **逐叶统计**：每条放行记录走完 5 棵树；同一记录在不同树上命中的叶分别计数，
  因此一条记录可同时为多个叶贡献样本。表中列出每个叶的路径限制（另附合并后的原料克数区间）、
  放行样本数、其中实测不合格数与比例。没有放行记录的叶同样列出并标为「证据不足」。
- **95% 同时置信核查**：全部叶（当前模型为 40 个）逐一计算单侧 Clopper–Pearson 下界，
  显著性水平用 Bonferroni 校正为 `0.05 / 叶总数`。Bonferroni 对任意相关结构成立，
  故同一记录被多个叶重复计数不影响同时覆盖率。
- **判定**：仅当某叶的校正后下界**严格大于**所填风险上限时，标「建议暂停自动放行」；
  其余一律「证据不足」——包括没有放行记录、或下界未超过上限的叶。不给出其他结论。
- **编辑即撤回**：修改抽检数据或风险上限，旧报告立即撤下（同时中止在途请求）；
  迟到的响应按 epoch 丢弃，绝不恢复旧报告。仅修改输入而未重新核查时，页面明确提示「已撤下」。

## API

| 端点 | 说明 |
| --- | --- |
| `GET /` | 试配筛选网页 |
| `GET /audit` | 局部风险核查网页 |
| `GET /api/meta` | 模型规格（树数、深度、种子、阈值、特征名） |
| `GET /api/samples` | 经求解器实测的可行 / 无解样例 |
| `POST /api/solve` | 求解；体：`{original, lower, upper, locked}`（各 4 元） |
| `GET /api/audit/leaves` | 全部叶节点的路径限制、原料区间与叶内合格概率 |
| `GET /api/audit/sample` | 固定种子的示例抽检数据（含风险上限建议值） |
| `POST /api/audit` | 核查；体：`{records: "多行文本", risk_limit: 0.05}`，返回逐叶统计与判定 |

## 完成说明（据实）

**已实现**

- 试配筛选（原有，保留可用）：合成数据 + 固定种子随机森林（5 棵树、深度 ≤ 3）；z3 按原分类器
  真实阈值语义编码；两阶段字典序最优求解；每份建议用原分类器复算；四种结果状态严格区分；
  可行/无解样例（启动时实测）；计算期可修改、修改即撤回、迟到结果不恢复。
- 局部风险核查（新增，`app/audit.py` + `app/static/audit.html`）：30～300 行四料抽检文本解析
  与逐行校验；按原分类器 float32 比例口径筛出放行记录；逐叶（全部 40 个叶）统计放行数与实测
  不合格比例，同一记录命中多叶时分别计数；对全部叶做 95% Bonferroni + Clopper–Pearson
  同时置信核查，仅在下界严格大于风险上限时判「建议暂停自动放行」，其余「证据不足」；
  修改抽检数据或风险上限立即撤下旧报告且迟到响应不恢复；顶部导航互通两页；Docker Compose
  启动后浏览器即可使用。

**已验证**

- `tests/selftest.py` 67 项检查全部通过（含 float32 阈值逐点核对、7,236,071 点全可行域
  枚举复核无解样例、最优性双重核对、逐叶计数与独立走树一致、同时置信边界用例）。
- `tests/frontend_test.js` 10 项 + `tests/audit_frontend_test.js` 26 项检查全部通过：以 DOM 打桩 +
  Node 直接执行页面真实脚本，验证「修改即撤回、迟到结果不恢复」与核查页渲染（未使用真实浏览器）。
- 本机以 uvicorn 实际启动服务，`curl` 验证 `/`、`/audit`、`/api/meta`、`/api/samples`、
  `/api/solve`、`/api/audit/leaves`、`/api/audit/sample`、`/api/audit` 的可行 / 无解 / 非法输入
  分支均返回正确结构；用「放行记录全部不合格」的实际请求验证 7 个叶被判暂停、用「全部
  未放行」的请求验证 40 个叶均为证据不足；两个页面内嵌 JS 均通过 `node --check`。

**未验证 / 限制**

- 本环境无 Docker，`docker compose up` 未实际执行；Dockerfile 中的每条命令（pip 安装
  相同钉版依赖、uvicorn 启动同一应用）已在本机逐一验证，compose 文件经 YAML 解析检查。
  新增的 `scipy` 已钉版写入 `requirements.txt`（它本就是 scikit-learn 的依赖，此处显式声明）。
- 前端测试为 DOM 打桩环境，未在真实浏览器中渲染验证样式与交互细节。
- 概率阈值判定含 1e-9 浮点容差（远小于该森林可取概率值的最小间隔约 1e-4），
  用于吸收 float64 求和顺序差异，见 `app/model.py: PROBA_EPS`；核查页的放行判定复用同一口径。
- 置信区间按「每叶放行记录」作独立同分布样本处理；抽检样本若有重复配方或批次聚集，
  实际覆盖率可能低于名义 95%（Bonferroni 只保证跨叶的同时覆盖，不修正叶内相关性）。
